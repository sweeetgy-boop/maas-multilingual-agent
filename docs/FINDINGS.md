- `ko-023` 여권 만료 규정 → 도메인 안으로 잘못 판정

**의도 정확도 붕괴가 결정타다.** 53.3% → 17.8%. 의도가 틀리면 잘못된 도구를
호출하고 α 가 64%까지 올라가 비용 절감 효과가 사라진다.

**1.7B 가 4B 보다 느렸다.** 반직관적이지만 작은 모델이 출력을 장황하게 내면서

## 3. Bedrock Guardrails 다국어

### Classic vs Standard tier

동일 정책으로 두 tier 를 만들어 비교했다.

| 입력 | 기대 | Classic | Standard |
|---|---|---|---|
| 제주도 맛집 좀 추천해줘 | 차단 | **NONE** | INTERVENED |
| 서울역에서 부산역 KTX 시간표 | 통과 | NONE | NONE |
| Buatkan itinerary 3 hari di Busan | 차단 | INTERVENED | INTERVENED |
| Jadwal kereta dari Seoul ke Busan | 통과 | — | NONE |
| 株式投資のおすすめを教えてください | 차단 | — | INTERVENED |

**Classic tier 는 한국어를 전혀 잡지 못한다.** 인도네시아어가 걸린 건 라틴
문자라 영어 모델이 부분적으로 반응한 것이지 지원이 아니다.

### Standard tier 생성 시 필수 설정

```json
{
  "topicPolicyConfig": { "tierConfig": { "tierName": "STANDARD" } },
  "contentPolicyConfig": { "tierConfig": { "tierName": "STANDARD" } },
  "crossRegionConfig": { "guardrailProfileIdentifier": "apac.guardrail.v1:0" }
}
```

cross-Region inference 를 지정하지 않으면 Standard tier 가 동작하지 않는다.

### 주제 정의 길이 제한

`definition` 은 200자를 넘으면 `ValidationException` 이 발생한다.
초기 정의(400자)가 거부되어 압축했다.

### 숙박 문의 오탐

`NonTransportAdvice` 정의에 "tourism itineraries" 를 넣었더니 **"광명역 근처
호텔" 이 차단**됐다. 숙박은 서비스 범위 안이므로 정의에 명시적 예외를 추가했다.

```
"...Searching for a hotel near a station is NOT in this topic."
```

**가드레일 정의와 게이트 프롬프트의 도메인 경계가 어긋나면 이런 충돌이 난다.**
두 곳을 함께 관리해야 한다.

## 4. 직접 구현한 방어 계층

Guardrails 가 커버하지 못하는 부분을 코드로 메웠다.

### 금지어 우회 탐지

| 우회 기법 | 예시 | 대응 |
|---|---|---|
| 자모 분리 + 공백 | `ㅅ ㅂ` | NFKC 정규화 후 구분자 제거 |
| 별표 마스킹 | `f*ck`, `an**ng` | 마스킹 문자를 와일드카드로 1:1 치환 |
| 제로폭 문자 | `f\u200buck` | U+200B~U+200F 제거 |
| 동형 문자 | 키릴 `о` → 라틴 `o` | translate 매핑 |

**함정: NFKC 정규화가 호환 자모를 조합 자모로 바꾼다.** `ㅅ`(U+3145)이
U+1109 로 변환되어 사전과 매칭이 깨졌다. **사전 어휘에도 동일 정규화를
적용해야 한다.**

### PII 정규식

**함정: `\b` 가 한글 조사 앞에서 성립하지 않는다.**

```python
# 실패: "M12345678로" 에서 뒤쪽 \b 가 성립하지 않음
r"\b[A-Z]{1,2}\d{7,8}\b"

# 성공
r"(?<![A-Za-z0-9])[A-Z]{1,2}\d{7,8}(?!\d)"
```

한국어 서비스에서 영문 정규식을 그대로 쓰면 흔히 나오는 문제다.

### 근거성 검증 (contextual grounding 대체)

답변에서 숫자·시각을 추출해 도구 응답과 대조한다. 불일치 시 재생성하고,
재생성 후에도 실패하면 답변을 폐기한다.

**실제로 작동한 사례**: 게이트가 의도를 `get_realtime_status` 로 오분류해
시간표가 없는 도구 응답이 넘어갔는데, Haiku 가 **KTX 1234편 / 14:00 출발 /
59,000원을 통째로 지어냈다.** 검증 계층이 환각 숫자 10건을 잡아 재생성시켰다.

```
"unsupported_numbers": ["14:00","5678","17:10","9012","14:30",
                        "59,000","1234","16:10","15:00","16:40"]
```

이 계층이 없었으면 가짜 시간표가 사용자에게 나갔다.

## 5. vLLM 운용 실패 사례

### Qwen3 추론 모드

기본값이 추론(thinking) 모드라 `<think>` 블록이 출력 토큰을 다 소모한다.
80토큰 상한에서 답변이 시작조차 되지 않았다.

```json
"chat_template_kwargs": {"enable_thinking": false}
```

요청 파라미터로 해결. 재기동 불필요.

### 구조화 출력 폭주

**중첩 스키마에서 xgrammar 가 제약을 놓친다.** `pii_spans`(객체 배열)와
`slots`(중첩 객체)를 쓴 스키마에서 90문항 중 36건이 파싱 실패했다.
출력이 6,800자까지 폭주했다.

→ 스키마를 평탄화(flat)하고 파이썬에서 재구성했다. 파싱 실패 0건.

**마지막 필드에서도 폭주가 발생한다.** `confidence` 를 마지막에 두었더니
값을 못 채우고 공백을 무한 생성했다 (512토큰 소진).

```
"pax": 1
  \n    \n    \n  \n    \n    \n  ...
```

→ 사용하지 않는 `confidence` 필드를 제거해 해결.

### GPU 메모리 배분

한 GPU 에 세 모델을 동시에 올리려다 전부 실패했다.

```
Available KV cache memory: -9.08 GiB
ValueError: No available memory for the cache blocks.
```

`--gpu-memory-utilization 0.42` (19.3GB) 로 8B(가중치 15.3GB)를 올리려 했으나
CUDA 그래프와 활성화 메모리를 포함하면 예산을 초과한다.

→ **순차 실행으로 전환.** 모델을 하나씩 올리고 교체하는 방식이 확실하다.

### L4 에서 4B 처리량

```
Avg generation throughput: 7.4 ~ 11.0 tokens/s
```

L4(약 300GB/s)는 4B bfloat16(8GB)을 감당하기에 메모리 대역폭이 부족하다.
평가 중 타임아웃이 연쇄 발생해 90문항 중 48건이 실패했다.

→ 모델 성능이 아니라 하드웨어 병목. L40S 로 재측정해 정상 결과를 얻었다.
